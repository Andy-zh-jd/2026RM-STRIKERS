
## 烧完怎么判断是"对的固件"

**现象级判据（3 条，全过才算成功）**

1. RGB 灯在变色（= TIM10 的 1 ms 中断活着）
2. 串口两行交替滚动，各约 5 Hz：
   ```
   gx=.. gy=.. gz=.. ax=.. ay=.. az=.. vbat=..
   r1=.. r2=.. r3=.. r4=.. tgt=.. stop=.. sL=.. sR=.. col=..
   ```
   > `DBG_MINIMAL 1` 下 IMU 那行是**旧值/零**，这是预期的，不是坏
3. `vbat` 与实际供电相符：USB 供电 ≈ **4.10**，6S 电池 ≈ **25.9~26.1**

**二进制级判据（怀疑烧错版本时用）**

```powershell
# 前 8 字节 = 初始栈顶 + 复位向量
$b=[IO.File]::ReadAllBytes("RM_Frame_C.bin")
"SP=0x{0:X8} Reset=0x{1:X8}" -f [BitConverter]::ToUInt32($b,0),[BitConverter]::ToUInt32($b,4)
```
本包固件应为：

```
SP    = 0x20020000      （SRAM 末尾，正确）
Reset = 0x08007555      （奇数 = Thumb 位正确；.isr_vector 在 0x08000000，长度 0x188）
```

## 烧录常见故障

| 现象 | 原因 / 处理 |
|---|---|
| `No available debug probes are connected` | ST-Link 驱动没装（`stsw-link009`）或线是充电线 |
| 串口 `ClearCommError / PermissionError 13` | 烧录把板子复位了、USB 重新枚举；烧前关串口窗口，烧后等 2 s |
| 串口在、打不开（`Cannot configure port, OSError 22`）| **当前固件里有阻塞调用**（IMU SPI 读）→ 换回 `DBG_MINIMAL 1` 的固件 |
| 板子每 1.02 s 重启一次 | 看门狗没人喂：`Device.cpp` 的喂狗被改成条件喂了（本包已修成无条件）|
| 灯不亮 / 不跑 | SWD 是不是接了 5 V（会烧 IO）；或供电只有 USB 且外设要 24 V |

## 烧完想立刻验证的三件事

1. **遥控**：拨 SC 下档 → 串口 `sR=158`；推右摇杆上 → `col` 变正、`tgt` 跟着变
2. **电机回传**：手转 M2006 输出轴 → `tgt` 不变但 `rpm` 出现负值；`r1~r4` 在没接底盘电机时应为 0
3. **安全态**：拔掉接收机 → `stop` 必须回到 **1**（电机不解锁）。若 `stop=0`，说明 `RemoteAlive()` 被改坏了
