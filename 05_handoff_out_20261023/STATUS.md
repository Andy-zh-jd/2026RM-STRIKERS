## 5. 当前最大卡点：IMU 拖死 USB（未根治）

**现象**：USB 能枚举成 `USB 串行设备 (COM5)`、PnP 状态 OK，但打开永远报
`Cannot configure port, OSError 22 参数错误`。换线/换口/拔 24 V/关终端都无效。

**定位**：烧一个跳过 IMU 的固件 → 串口立刻正常；加回 IMU → 立刻复现。

**机制**（这条最有价值）：`HAL_SPI_TransmitReceive(..., Timeout)` 内部用 `HAL_GetTick()` 判超时，
而这段代码跑在 **TIM10 的 1 ms 中断**里，SysTick 优先级低于它 → **tick 不再递增** →
`(HAL_GetTick()-Tickstart) > Timeout` 永不成立 → **死循环**，1 ms 中断回不来，
USB 控制传输没机会响应 → 设备在、口打不开。

**已做**：
- SysTick 优先级提到 0（修 HAL 超时在中断内失效）→ **仍复现**
- SPI 超时 100 ms → 1 ms + 连续失败 5 次熔断 → 仍复现
- 新增 `tools/read_swd.py`：USB 打不开时用 ST-Link 直读 `g_dbg[8]` 快照，绕过 USB CDC
- 临时用 `DBG_MINIMAL 1` 运行

**待验证的猜想**（按可能性排序）：
1. **BMI088 硬件/焊接**问题（读 chip id 也要走 SPI，但 chip id 曾经是好的：aid=30/gid=15）
2. SPI 时序/模式（Mode 3、预分频 256）在某些状态下挂死
3. 该把 SPI 读改成 **DMA + 状态机**（非阻塞），彻底不占中断

> 注意：**IMU 不是 M3/M4/M5 的硬依赖**。四轮闭环用电机自带编码器，航向闭环才需要 IMU。
> 所以正确顺序是：**先把四轮走起来，IMU 单独立项查**。

## 7. PID 调参的实测结论（可直接复用）

| 配置 | 目标 | 实测 | 静差 |
|---|---|---|---|
| 纯 P（`kp=60, ki=0`）| 20.7 | 14.3 | **30%** |
| **P+I（`ki=0.5, componentKiMax=6000`）** | 7.49 | 7.42 | **0.9%** |

**两条铁律**：
1. `errSum += err` **不乘 dt**（`Motor.cpp:22`）→ 固件里 `ki` 量级是 **0.1~1.0**，不是仿真里的 10
2. `ki` 必须和 `componentKiMax` **一起改**；限幅公式是 `INRANGE(errSum, ±componentKiMax/ki)`，
   `componentKiMax` 默认 0 → 只改 `ki` 等于没加 I
