# 电池一插上，板子可能每 1 秒重启一次（**已修，2026-10-17**）

> ✅ **已经改好了**：`Device.cpp:202` 改成**无条件喂狗**，并把电压判断挪出喂狗条件（只留注释占位）。
> 另外在 `UserTask.cpp` 的 100 ms 打印里加了 `vbat=`，接电池后能直接看到读数。
> 下面留着，因为这是**这类 bug 的完整推理过程**，下次别把业务判断塞进喂狗条件里。

交接包里 `Device.cpp:274` 已经把 `MX_IWDG_Init();` 打开了（IWDG 超时 = 8×4096/32k ≈ **1.024 s**）。
但 1 ms 主循环里的喂狗是**有条件**的：

```c
// Device.cpp 199~205 行（1 ms 中断里）
if (cnt > 20) {
    if (vccBat < 10) HAL_IWDG_Refresh(&hiwdg);   // ← 只有电压读数"低"才喂
    cnt = 0;
}
```

现在真正稳定喂狗的地方只有两处：
1. **DBUS 中断**收到一帧合法遥控数据（`sbus_rx_buf[..][23] == 0`）
2. **`IMU_Calibrate()`** 那 1 秒

所以会出现这种情况：

| 场景 | `vccBat` 读数 | 结果 |
|---|---|---|
| 只用 USB-C 供电（没电池） | ≈ 0 → 满足 `<10` | 正常喂狗，一切正常（之前"跑了 143 秒无复位"很可能就是这样） |
| **接 24V 电池** | 大概率 ≥ 10 → 条件不成立 | **没人喂狗 → 每 1.02 秒复位一次** |
| 接电池 + 遥控器已对码并持续发帧 | 无所谓 | 由 DBUS 中断喂狗，正常 |

而且 `vccBat = vccMoni / 22.0f * 222.0f`（`Device.cpp:153`）这个换算**很可能是笔误**（除非硬件分压是 10:1 左右）。所以到底落不落在 10 以上，**必须实测**，别推理。

## 上电池前 3 分钟做的事

1. 在 `UserTask.cpp` 顶部加一行 extern（`vccBat` 没写在任何头文件里）：
   ```c
   extern volatile float vccBat;
   ```
2. 在 `UserHandle()` 的 100 ms 打印里临时改成先打电压：
   ```c
   UsbPrintf("vbat=%.2f\r\n", vccBat);
   ```
3. 接电池上电，看串口：
   - 读数 **< 10** → 暂时没事，但换算要修（用万用表量电池实际电压，反推系数）
   - 读数 **≥ 10** → 立刻做下面 A 或 B，否则你会以为是 IMU 或供电坏了，白查两小时

## A. 最快的保命做法（推荐先这样）

把 `Device.cpp:274` 改回注释，先让板子稳定跑：
```c
// MX_IWDG_Init();   // 电池台架测试期间先关，等喂狗逻辑改对再开
```

## B. 正确的做法

把喂狗改成无条件，电压低的事交给别处处理（这才是看门狗该有的用法——它只该抓"程序卡死"，不该抓"电压低"）：

```c
if (cnt > 20) {
    HAL_IWDG_Refresh(&hiwdg);      // 无条件喂
    if (vccBat < 20.0f) { /* 低压保护：限流/停机，用实测阈值 */ }
    cnt = 0;
}
```

同时把 `IMU_Calibrate()` 里的那行 `HAL_IWDG_Refresh(&hiwdg);` 留着（标定要跑 1 秒，本来就跨过超时）。

> 规则里"警告 = 整车断电 5 秒"，断电再上电时这套初始化要能干净重来一次。看门狗喂法正确，才不会把"被裁判断电"和"自己复位"混在一起。
